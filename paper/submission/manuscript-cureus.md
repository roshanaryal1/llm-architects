# Large Language Models as Systems Architects: A Controlled Study of Consensus, Fabrication, and Constraint Reasoning on One Hard Design Task

## Abstract

**Background:** Closed benchmarks with a hidden answer key dominate large language model (LLM) evaluation, yet many real tasks have no single correct answer. We treat one such task, designing a 24/7 autonomous AI development-and-research workstation for a 32 GB Apple M6 Mac mini, as an evaluation problem: an open-ended design with no ground-truth solution but many individually falsifiable sub-claims, such as whether a model fits in 32 GB, whether a named tool exists, and whether a response contradicts itself.

**Methods:** We gave one identical, evidence-demanding prompt to eleven frontier LLM systems and collected thirteen verbatim responses, extracted a 39-axis decision matrix, scored every response on a nine-dimension 0/1/2 rubric with four raters scoring independently (one author-derived baseline and three frontier LLMs on an identical packet), web-verified every factual sub-claim against sources fixed to the capture window, and checked memory feasibility with a standard-library estimator.

**Results:** Four results stand out. First, across the 39 axes the systems converge almost unanimously on the shape of the machine (one large model resident at a time, a coordinator/worker topology, durable SQLite state, Apple-Silicon-native inference, private-network remote access, least-privilege isolation) while splitting on the products that realise each choice. Second, the study-internal rater, itself an LLM, flagged 14 tools and models as hallucinated; on web verification none of the 14 was confirmed nonexistent and at least 12 are real releases dated after that rater's training cutoff. This is a rater failure, not an absence of defects: independent verification did find genuine factual errors elsewhere, none of them among the 14 flags. Third, citation quantity did not predict citation quality; the response with the largest reference apparatus (99 URLs) was the least reliable. Fourth, in the one system captured in multiple reasoning modes, mode moved the response a full grounding-and-fabrication tier with weights and prompt held fixed.

**Conclusions:** On a task where technical currency matters, an LLM asked to grade another LLM's factual grounding penalises the newest, best-grounded answers hardest, because the grader's own knowledge is stale. Any evaluation pipeline that places an LLM in the grader's seat for currency-sensitive questions needs an external verification step in front of it. We release the corpus, the rubric, four rater score sets, a web-verified register, and standard-library checking scripts.

**Keywords:** large language model evaluation; LLM-as-judge; training-cutoff bias; reference hallucination; inter-rater agreement; prompt sensitivity; systems architecture; reproducible benchmark corpus

## Introduction

Closed benchmarks dominate LLM evaluation: a task with a hidden answer key, a scalar score, and a leaderboard. Systems architecture is not that. Given a hardware envelope and a requirements list, there is no single correct design, but there are many claims inside any proposed design that are individually checkable: does this model fit in 32 GB? does this tool exist? does this version number resolve? does the response contradict itself?

This paper treats "design a hard system under a fixed consumer-hardware constraint" as an LLM task and measures it. The task is deliberately stress-inducing along several dimensions. The hardware is new: the Apple M6 Mac mini was announced on 25 August 2026, six days before the study. The memory ceiling of 32 GB unified memory is tight enough that a single wrong model choice breaks the design. The prompt explicitly asks for sources and for a list of things not to build.

The contributions are a reusable protocol for evaluating open-ended architecture responses (verbatim capture, structured extraction into a 39-axis decision matrix, a nine-dimension 0/1/2 rubric, multi-rater scoring with reported agreement, and automatable falsifiable-sub-claim checks); an empirical consensus map across eleven systems; a characterisation of fabrication on this task that turns out to be mostly a characterisation of the LLM rater; constraint-reasoning and recency results, including a memory-fit checker showing that every co-resident model set a response describes as simultaneously loaded exceeds 32 GB; a citation-quality analysis and a reasoning-mode sensitivity result; and a synthesised reference architecture together with a frank limitations section that includes a methodological error we made and its fix. The study is descriptive and exploratory: with thirteen captures it establishes patterns and failure modes on one instrument, not population-level laws, and we are explicit throughout about which claims are corpus observations and which are candidates for generalisation.

Agentic benchmarks such as SWE-bench and its variants [1], WebArena [2], and others including Terminal-Bench, OSWorld, Tau-Bench and AgentBench all score against an execution oracle: the task has a hidden pass or fail, and the scope has widened from function-level generation to environment-grounded interaction, but the answer key is always present. A survey of the agent-systems landscape [3] and benchmarks of frontier LLMs on real-world assistant tasks [4] describe the same oracle-based setting. Constrained design has no such oracle. We take the stance of scoring only falsifiable sub-claims, and measuring consensus rather than correctness, from systematic-review methodology: PRISMA-S for reporting a reproducible search [5], PRESS for peer-reviewing a search strategy [6], and the National Academies framing of reproducibility and replicability [7].

Using an LLM to score another LLM's output is now standard and its failure modes are catalogued. A survey of LLM-as-a-judge practice [8] documents position bias, verbosity bias, and self-enhancement; a large-scale study across twenty NLP evaluation tasks [9] finds that LLM judges vary substantially by task and must be validated against human annotations before use; and a controlled analysis [10] shows that a judge's ranking can be reversed simply by changing response order, and proposes position calibration as a fix. The standard fixes are randomised ordering, repeated runs, and rubric-based scoring that constrains the judge to factual criteria, which is exactly the instrument we use. Our result adds a bias not on those lists: a training-cutoff recency bias in which, when the judged content is more current than the judge's own knowledge, the judge systematically emits false-positive fabrication flags.

The hallucination literature supplies our fabrication vocabulary. A survey of hallucination in large language models [11] separates factual contradiction from factual fabrication, meaning generated content whose facts cannot be verified against any source; that fabrication category is the one our verification register applies to unresolvable tool and model names. Empirically, a controlled study of ChatGPT-generated bibliographies [12] found 55 percent of GPT-3.5 citations and 18 percent of GPT-4 citations fabricated outright, with 24 to 43 percent of the non-fabricated citations still carrying substantive errors; a comparative analysis for systematic reviews [13] reported reference-hallucination rates between 28 and 91 percent and reference precision below 14 percent for every model tested. Recently published content is a recognised knowledge-boundary cause of this behaviour. Our contribution moves that same cutoff mechanism from the author to the judge: it is not only that a model with an old cutoff invents post-cutoff sources, it is that a rater with an old cutoff flags real post-cutoff artefacts as invented.

Line-level and repository-level code generation is heavily studied, with SWE-agent, AutoCodeRover, Agentless, and OpenHands exploring different issue-resolution agent designs. Whole-system design under a fixed resource envelope is not; the nearest analogue is human-expert capacity planning. We treat "produce a deployable architecture from a hardware spec plus a requirements list" as an evaluable LLM task.

## Materials and Methods

We follow published guidance on reporting empirical software-engineering studies that involve LLMs [14]: this section declares the LLM usage and role, reports model, version, interface and browsing state per capture, releases the prompts verbatim, records session provenance in each capture's metadata, and includes an open-weight system in the corpus.

### The task instrument

The frozen prompt has a responder-context header that fixes the date at 31 August 2026, asks the model to declare its browsing state and version, and requests a Sources list. The task body asks for a 24/7 autonomous development-and-research workstation on a 32 GB Apple M6 Mac mini (12-core CPU, dual 16-core Neural Engine, 170 GB/s memory bandwidth, 512 GB internal plus 1 TB external SSD), coordinating "100+ logical agents without running 100 LLMs", remotely controllable, and securely sandboxed. It asks for deliverables A to K including an exact install plan and a list of what not to install. Two controlled variants are also frozen: one is a full paraphrase using request-for-comments framing with reshuffled sections and no shared sentences, and one is the base prompt with its anti-anchoring steer removed. Both were re-run on a five-system subset; those results appear under prompt sensitivity. Every other matrix and ranking in this paper is for the base-prompt captures.

### The response corpus

Thirteen captures were collected on 31 August 2026 from eleven systems (Table 1). One system, DeepSeek, contributes three reasoning-mode captures of one base model. Consensus analysis counts one canonical column per system, giving 10 non-anchor systems; the fabrication and internal-consistency analyses use all 13 captures, because the three DeepSeek modes are a within-model sensitivity measurement no other vendor provided.

The anchor capture, from Anthropic's Claude Sonnet 5, ran inside the same tool used to build this study's repository, with live browsing and partial authorship of the requested output format. It is retained as the consensus anchor and the only sourced baseline, and is excluded from every independent-sample aggregate. The unit of analysis is the system capture, meaning a product interface plus its routing, model, system prompt, browsing state and mode, not an isolated model.

### Extraction and rubric scoring

For each capture we retain a verbatim raw response, which is never edited after merge except for a dated correction note, the model's own cited-sources list, and structured reviewer notes, plus one short phrase per decision axis in a 39-axis matrix. Scoring uses a nine-dimension 0/1/2 rubric: hardware-constraint adherence (D1), recency (D2), tool factuality (D3), model factuality (D4), benchmark factuality (D5), citation quality (D6), actionability (D7), security model (D8), and internal consistency (D9). Axis coding used predefined inclusion criteria; for example, "Apple-Silicon-native inference" counts MLX-family runtimes and llama.cpp with Metal, not CPU-only inference. The 39 axes were defined by the author, which introduces researcher degrees of freedom; the coding guide and the per-response phrases are released so the coding can be audited. The rubric mixes two layers, and we do not claim to establish an objective ground truth for overall architectural quality: some dimensions are objective, such as model existence, version existence, memory feasibility under stated assumptions, and self-contradiction, while others are rubric-based judgements of design quality, such as actionability and security adequacy.

### Rater procedure and inter-rater agreement

The nine-dimension rubric was applied independently to all thirteen captures by four raters: one author-derived baseline and three frontier LLMs (GPT-5.6 Sol, Grok 4, and a DeepSeek chat run) given the identical scoring packet. "Independent" here means each scored the same packet without seeing another rater's scores; it does not mean design-independent, because the author-derived baseline also wrote the rubric and the reviewer notes. We therefore treat that rater as an author-derived baseline rather than a neutral fourth opinion, and use GPT-5.6 Sol as the canonical comparison rater. Agreement is reported as exact and within-one-point agreement, Cohen's kappa unweighted and quadratic-weighted [15], Krippendorff's ordinal alpha [16], Gwet's AC1 unweighted and quadratic-weighted [17], and, for the per-response totals, Spearman's rho and Kendall's tau-b between every rater pair. The estimator is a released standard-library script.

Two scoring passes exist and are not interchangeable. In the full four-rater pass an intermediate version of the packet listed 12 real post-cutoff tools in one rule while instructing raters to treat them as real; all three second-rater runs saw it. That pass is kept for agreement statistics only, not for the two factuality dimensions. A clean re-run of dimensions D3 and D4 used an uncontaminated packet that names nothing, forbids reading the verification register, mandates web verification, and scores an unresolved entity as 1. That clean pass is canonical for the D3 and D4 levels. One of the two fresh raters used for it, Perplexity, was discarded because it scored tool factuality 0 for seven responses by treating its own search misses as evidence of non-existence.

### Fact verification

Every falsifiable sub-claim is recorded verbatim and checked. Tool and version existence is checked against a registry or repository fixed to the capture date, and the per-entity verdicts (entity exists, identity correct, attribute correct, claim supported, and a final category) are released as a register. URLs in a response's citation apparatus are classified on three axes: whether the URL resolves, whether it supports the claim it is attached to (fully, partly, or not), and whether the source is primary, secondary, tertiary, or irrelevant. "Non-supporting or unresolvable" is the union of does-not-resolve and does-not-support.

### Memory-budget estimation

A standard-library estimator computes weights plus key-value cache for a response's co-resident model set, meaning what the response says stays loaded, against 32 GB. "Fails to fit" is defined against a fixed non-model reserve: macOS plus WindowServer at about 5 GB, a headless browser at about 1.5 GB, the Python worker pool plus runtime at about 2 GB, SQLite plus a vector index at about 1 GB, and a 2 GB safety floor, totalling about 11.5 GB, plus a key-value cache sized at the response's own stated context length at 8-bit precision. Weight sizes are the actual 4-bit GGUF or MLX artefact sizes where published, otherwise the parameter count multiplied by 0.5 bytes plus 8 percent runtime overhead. The script prints every line item and takes the reserve as overridable flags.

### Use of AI tools in this study

This is disclosed in full because the study's subject is AI systems. The consensus anchor is a frontier LLM run inside an AI coding tool with live browsing and partial authorship of the requested output format; it is excluded from every cross-response aggregate. The repository, meaning the analysis scripts, the data plumbing, and drafting of parts of this manuscript, was produced with an AI pair-programming assistant; every script uses only the Python standard library, is in the release, and its outputs are reproducible from the released comma-separated files. Three of the four rubric raters are frontier LLMs, by design, because that is the object of study. All numeric results in this paper were regenerated from the released artefacts by running the released scripts; no result is quoted from an un-scripted model statement. No AI-generated images are used, and no part of the analysis beyond copy editing and code assistance was delegated to a model without human verification.

## Results and Discussion

### Architectural consensus

Across the 39 axes the systems are unanimous or near-unanimous, at nine or all 10 non-anchor systems, on the shape of the machine. They agree on Apple-Silicon-native inference as the primary path, with llama.cpp and Ollama compatibility; on keeping one large model resident at a time with small models optional or on demand, the lone outlier being a design that proposes two or three co-resident instances and is separately shown to violate the memory budget; on model swapping with an anti-thrash policy; on a custom supervisor with thin integration of specialist runtimes rather than one mega-framework; on a hierarchical coordinator/worker topology that is explicitly not a swarm; on treating "100 agents" as cheap state and configuration rather than 100 resident models; on one concurrent heavy-inference slot; on an evidence-first research pipeline with a stored evidence ledger, where final prose is generated only from verified evidence; on SQLite plus the filesystem as day-one memory, deferring vector and graph complexity; on a dedicated non-admin user plus workspace isolation as the security boundary; on a Tailscale-only private network with no public exposure and a small private dashboard; on launchd with KeepAlive plus an independent watchdog, with caffeinate or pmset on AC power, and a durable queue with leases, checkpoints and requeue that never replays destructive actions; on 32 GB unified memory being the bottleneck rather than CPU or GPU compute; and on the 1 TB external SSD being cold storage rather than the latency-critical disk. The memory-bottleneck point is a corpus observation: all 10 non-anchor responses identified memory as the primary constraint, and our independent memory model is consistent with that interpretation.

Where the systems disagree, they disagree on products, and we record those axes as adjudication points rather than facts (Table 2). We can put a number on the split. Tagging each of the 33 architecture axes as structural (topology, state model, security boundary, concurrency stance, memory architecture; 24 axes) or product (which named tool or model realises a layer; nine axes) and taking the modal-agreement count per axis over the 10 non-anchor systems, we find that the structural axes have a median modal agreement of 10 out of 10, with 18 of 24 at nine or higher, while the product axes have a median of 5 out of 10, with only one of nine at nine or higher: a five-point gap. The classification and the per-axis counts are in a released script so the tagging can be audited. The result is that the systems agree on constraints and topology and disagree on implementation at the boundary of those constraints, which separates robust architectural principles from fast-moving product preference more cleanly than a superficial majority vote would.

### Apparent fabrication and the rater that generated it

The study-internal rater, an LLM with a training cutoff around January 2026, audited every capture and flagged 14 tools and models across five responses as fabricated, most heavily in the two DeepSeek fast modes and in the Meta Llama 4 capture. We initially drafted a "cross-vendor shared hallucination" finding around two tools each named by three vendors.

Web verification against 2026 sources overturned that reading (Table 3). None of the 14 flagged entities was confirmed nonexistent, and at least 12 are real releases dated after the rater's training cutoff. Of the seven names that were unresolved at first pass, a follow-up verification pass resolved three (Cloak at getcloak.dev, memo at jagoff/memo, and pi-search-hub at ronnieops/pi-search-hub) to real projects, leaving four genuinely unresolvable: Helmrig, DiffResearch, cplt, and agent-policy-engine. The false positives cluster precisely on the most current responses.

This is a statement about the 14 flags, not about the corpus. We keep three populations separate. The initial-rater fabrication flags are the 14 names, of which zero were confirmed nonexistent, at least 12 are real post-cutoff releases, and four remain unresolvable (Helmrig, DiffResearch, cplt, and agent-policy-engine). The wider set of flagged-or-doubted names reaches about 18 once later passes are included, still with zero confirmed nonexistent and the same four unresolvable. Separately, independent verification found genuine factual defects that were never raised as fabrication flags: one genuinely nonexistent future model in the DeepSeek deep-reasoning capture, several model-attribute errors in the Zhipu capture, and internal contradictions in several captures. So the corpus is not fabrication-free; the initial rater's fabrication verdicts were.

The catalogued LLM-as-judge biases of position, verbosity and self-enhancement [8-10] are all about how the judge is influenced by the candidate's form; this one is about what the judge cannot know, and it does not wash out with randomised ordering or repeated runs. The mechanism is more precisely a temporal epistemic misclassification: the evaluator treats absence from its internal knowledge, or an unsuccessful retrieval, as evidence that a post-cutoff entity does not exist. Training cutoff is one cause; retrieval failure is another. Our mitigation is that dimensions D3 and D4 of the rubric now require the rater to web-verify each name before scoring, and "not in my training data" scores 1 for unresolved, never 0. The failure mode also reproduced in a fresh rater given exactly that instruction: in the clean re-scoring one of two fresh raters treated its own search misses as evidence of non-existence for seven responses, and its scores were discarded.

The analysis is not empty of real defects (Table 4). These survive verification and remain in the analysis: a load-bearing model-size error and a self-contradiction on model memory size in the Zhipu capture; an incorrect M6 memory-bandwidth figure and an unreliable citation apparatus in the Meta capture; recommend-then-forbid contradictions in two DeepSeek captures; a nonexistent future primary model in the DeepSeek deep-reasoning capture; a memory oversubscription and a model-architecture error in the DeepSeek Instant-plus-DeepThink capture. The Grok 4 capture records no surviving factual defect: it states the full M6 specification, including 170 GB/s, correctly, and its alternate-tool list resolves entirely, so it does not appear in Table 4. Its only weakness is zero cited sources. We note this explicitly because an earlier draft mis-attributed a bandwidth error to Grok 4; the error belongs to the Meta capture only. The corrected picture is that the low-scoring responses are low-scoring for verifiable reasons, not for inventing an ecosystem.

### Constraint reasoning

Every co-resident set that a response describes as simultaneously loaded exceeds 32 GB once the fixed non-model reserve and the key-value cache are counted alongside the weights. The designs that fit are the ones that do not keep the heavy models co-resident. Designs that keep one large mixture-of-experts model resident, at about 17 to 20 GB at 4-bit, plus a small dense model swapped in, are tight but feasible, and several responses say so explicitly and reserve a 2 to 6 GB floor. Designs that keep two large models resident, or a dense 32-billion-parameter model plus a helper, exceed the ceiling at working context lengths. The clearest violation is a DeepSeek capture with about 32 to 34 GB of always-loaded weights before the operating system, browser, and key-value cache are even counted, whose text calls oversubscription acceptable; the second is a three-instance worker-pool diagram paired with a claim that it fits within 32 GB with swapping. Inter-rater agreement on this dimension is the lowest of the nine, at kappa 0.15, because "sums to exactly 32 GB with no reserved margin" was scored 1 by one rater and 2 by another; the hardened rubric requires a named free-RAM floor for a score of 2.

### Recency

The web-verified M6 facts are: announced 25 August 2026, 170 GB/s memory bandwidth at 24 to 32 GB (153 GB/s at 16 GB), and 32 GB maximum unified memory. Against those facts, two non-anchor responses plus the anchor engage the real M6 specification, hedge every throughput number, and cite sources. Six responses make current tool and model picks but provide no usable sources, and two of those also carry a roughly 12- to 18-month model lag. Two responses are behind on models, with previous-generation primaries and stale cloud-fallback lists. Only the Meta capture got a hard M6 fact wrong, at about 300 GB/s; the Grok 4 capture, which the first rater mistakenly grouped with it, states 170 GB/s correctly. Recency correlates with retrieval or browsing and with not being penalised by a stale rater, but it does not cleanly predict agreement with the cross-model consensus.

### Citation quality

Only the anchor and four non-anchor responses cite anything resolvable (Table 5). Citation quantity did not predict citation quality on this corpus, and because only five of 13 responses carry any citation apparatus we report the pattern rather than a correlation coefficient. The pattern is driven by the extremes: the Meta capture has the largest apparatus and the worst, with 59 of its 99 URLs non-supporting or unresolvable, the same tool given several different repository URLs, and one real preprint URL under the wrong title, whereas the GPT-5 capture cites zero URLs but every inline attribution points at a real, checkable source. Reference presence and evidential grounding are distinct properties. The consequence for evaluation design is that "has a Sources section" must not be used as a proxy for "is grounded", because scoring it that way ranks the Meta capture above the GPT-5 capture, which is backwards. Dimension D6 scores a mostly-unsupported apparatus as 0, and it is the cleanest single separator in the adjudicated scores.

### Internal consistency and reasoning-mode sensitivity

Material self-contradictions appear in three of thirteen captures: two DeepSeek captures each recommend a tool that their own do-not-install list forbids; the Zhipu capture gives one model two different memory sizes and pairs "primary model stays loaded, others on demand" with a three-instance co-resident diagram; and the Meta capture has coherent prose but an incoherent citation apparatus.

DeepSeek is the only system captured in more than one mode: three captures, one base model, three chat modes (Table 6). Within this single case study, holding weights and prompt fixed, the reasoning mode produced materially different factual and constraint profiles, spanning three of the rubric's coarse tiers. The effect is not monotone across every dimension: after the clean re-run the fast mode scores above the deep mode, because the deep mode's more elaborate upgrade path reached for future models that do not exist while the fast mode's picks all resolved. On this evidence, mode is at least as large a factor as the base-model label for a fixed DeepSeek family; whether that generalises across model families is an open question and the obvious controlled follow-up.

### Inter-rater agreement and performance bands

The four rater means span 11.1 to 14.7 of 18 (Table 7). For the canonical pair, over 117 paired ratings, exact agreement is 68.4 percent, within-one-point agreement is 96.6 percent, Cohen's kappa is 0.49 unweighted and 0.64 quadratic-weighted, Gwet's AC1 is 0.54 unweighted and 0.73 quadratic-weighted, and Krippendorff's ordinal alpha is 0.20 for the pair and 0.12 for all four raters. The gap between a weighted kappa of 0.64 and an alpha of 0.20 is a prevalence effect: several dimensions are dominated by 2s, which inflates chance agreement in the ordinal alpha, while Gwet's AC1, which is designed for that skew, sits with the weighted kappa. We read agreement as moderate and dimension-dependent. By dimension, recency, tool factuality and benchmark factuality are reliable, at kappa 0.66 to 0.70; citation quality, security model and actionability are weak; and hardware-constraint and internal-consistency are the weakest, at kappa 0.15 and 0.14.

Rank-order stability is limited, not established. Rank-correlating the per-response totals between every rater pair gives a mean Spearman rho of 0.36 and a mean Kendall tau-b of 0.28. The canonical pair is the tightest, at rho 0.71, but the two heavier-scoring raters diverge sharply, with the author-derived baseline against the DeepSeek run at rho 0.08. We therefore do not claim a stable fine-grained ranking. What survives across raters is coarse: the same responses land in the top and bottom bands (Table 8). The numeric total is a secondary summary and is always reported with the per-dimension kappa, never as a headline. Raters also have a severity personality, and the DeepSeek run assigned a 2 on five dimensions almost uniformly, behaving as a low-information rater; an LLM used as a rubric rater is not a portable instrument without anchored exemplars.

The answer-key leak in the intermediate packet was measured, not assumed. The clean re-run changed two canonical D3 and D4 cells directly attributable to removing the leaked list, and four additional D3 and D4 cells on verification evidence newly found during the clean pass; the canonical rater reproduced its contaminated D3 and D4 on 11 of 13 responses, and the top and bottom performance bands are unchanged. Dimensions D1, D2, and D5 to D9 were never contaminated.

### Prompt sensitivity

Five systems were re-run on the full paraphrase and on the anti-anchoring-steer ablation, for 15 captures in total. Across all 15, every response keeps its architecture, meaning the coordinator/worker topology, logical agents as data, one heavy plus one small model, SQLite state, a dedicated non-admin user, launchd, and Tailscale, and changes only which products realise each layer. Effect size is strongly model-dependent: one system's primary inference-engine pick is different in each of the three framings, while two others are almost invariant. The anti-anchoring steer does real work, but its sign is not uniform: removing it made two systems name more products and one system name fewer. Two of the five systems, the Zhipu z.ai and Google Gemini captures, served a different underlying model between paraphrase runs, self-reporting different knowledge cutoffs and model labels across sessions; only the GPT-5 and Perplexity captures held their model identity across all three framings, so the clean prompt-sensitivity comparison exists only for those two. This is a threat to validity that generalises to any study using a consumer chat product as an instrument. Across all ten paraphrase captures, zero fabrications were confirmed on web verification.

### Synthesised reference architecture

The following is an analytic synthesis, meaning majority positions plus adjudicated calls, not a consensus ground truth and not empirically validated as optimal. For inference, use one MLX-family runtime behind an internal adapter, with one large mixture-of-experts model resident at about 17 to 20 GB at 4-bit plus one small dense model swapped in on demand, and never two large models co-resident; benchmark the chosen runtime on the actual M6 before trusting any throughput claim. Represent the agents as SQLite rows or definition files under a hierarchical coordinator/worker topology with one concurrent heavy-inference slot plus two or three small or tool workers. Let a thin custom Python supervisor own task state and scheduling, with a framework used only for selected stateful workflows and kept replaceable. Make coding execution capability-tiered, with a git-native interactive editor for edits and a containerised autonomous agent for multi-step jobs. Run an evidence-first research pipeline in which every claim traces to a stored snippet, a second-pass verification agent re-opens sources, a contradiction pass runs, and prose is synthesised only from the verified ledger. Use the filesystem plus SQLite with full-text search on day one, add an embedded vector extension when needed, and defer a standalone vector daemon and a knowledge graph until a real need is demonstrated. Use a SQLite write-ahead-log task queue with leases and checkpoints, requeue interrupted work, and never replay destructive actions. For security, use a dedicated non-admin macOS user plus workspace isolation, capability tiers with a kill switch and per-task runaway limits, and secrets in the system keychain; scope stronger sandboxing to untrusted code rather than making it universal. For always-on operation use launchd with KeepAlive plus a separate watchdog plus caffeinate or pmset on AC power. For remote access use Tailscale only, with zero inbound ports and a small dashboard on the private network, and route approvals through the dashboard. Put the operating system, runtime and hot working state on the internal SSD and the model library, research corpus, datasets and backups on the external SSD. Treat cloud use as an explicit policy-gated escape hatch that keeps the system useful at zero cloud spend. The 32 GB unified-memory ceiling is a hard engineering constraint, not a target to fill.

### Limitations and threats to validity

The primary instrument is a single base prompt. Two controlled paraphrases on a five-system subset show that the architecture is stable across framings and that no new fabrications appear, so the consensus and fabrication findings are not phrasing artefacts, but the product-level results are somewhat phrasing-sensitive and should be read as "for this instrument"; a second hardware specification has not been tested. Consumer chat tiers are not reproducible instruments, since two of five systems served a different model between paraphrase runs. The anchor capture is not blind, and is handled by exclusion from every cross-response aggregate. Three of the four raters are frontier LLMs, and the fabrication result is a direct demonstration of the associated risk; the mitigations are mandatory web verification for factual dimensions, a human-authored rubric, four raters with reported agreement, and verbatim recording of every falsifiable sub-claim. The intermediate rater packet leaked part of the verification key, and the bounded re-run above measures the effect. Rater severity varies by about 3.6 of 18. Grok 4 scored the Grok 4 response and the DeepSeek run scored the three DeepSeek responses, which is noted but not corrected, since both are variance-check raters. The author-derived rater is not design-independent, which is why a canonical rater exists and the adjudicated bands are the reportable output. Every capture is a dated snapshot from 31 August 2026, and free-tier defaults will have moved by publication; we preserve the information state of the evaluation rather than claiming the live ecosystem is reproducible. The DeepSeek mode effect is one system and motivates, but does not establish, a general law.

### Broader impact

This work contributes a reusable protocol and a released corpus for auditing LLM-as-judge pipelines on open-ended technical tasks, and documents a specific, cheaply mitigated failure mode. The risks are that the released corpus and rubric could be used to game an evaluation, that "an LLM said it is fake" verdicts shown here to be unreliable may still be cited as authoritative, and that the synthesised reference architecture is a dated snapshot whose uncritical reuse past its 2026 currency window would reproduce the recency failure it documents.

## Conclusion

Asked to design the same constrained machine, eleven frontier LLM systems agree on what the machine is, a memory-bound local-first coordinator/worker workstation with durable state and private-network control, and disagree on which specific products build it, and those disagreements mark exactly the decisions a human engineer still has to adjudicate.

The sharper result is about evaluation. On a task where currency matters, an LLM asked to judge another LLM's factual grounding will penalise the newest, best-grounded answers hardest, because the judge's own knowledge is stale, so any evaluation pipeline that puts an LLM in the grader's seat for currency-sensitive questions needs an external verification step in front of it.

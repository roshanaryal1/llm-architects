# Large Language Models as Systems Architects: A Controlled Study of Consensus, Fabrication, and Constraint Reasoning on One Hard Design Task

## Abstract

**Background:** Closed benchmarks with a hidden answer key dominate large language model (LLM) evaluation, yet many real tasks have no single correct answer. We treat one such task, designing a 24/7 autonomous AI development-and-research workstation for a 32 GB Apple M6 Mac mini, as a case study in evaluation: an open-ended design with no ground-truth solution but many individually falsifiable sub-claims, such as whether a model fits in 32 GB, whether a named tool exists, and whether a response contradicts itself.

**Methods:** We gave one identical, evidence-demanding prompt to eleven frontier LLM systems and collected thirteen verbatim responses, extracted a 39-axis decision matrix, scored every response on a nine-dimension 0/1/2 rubric with four raters scoring independently (one author-derived baseline and three frontier LLMs on an identical packet), web-verified every factual sub-claim against sources fixed to the capture window, and checked memory feasibility with a standard-library estimator. Sensitivity analyses remove the author-derived rater, remove weakly reliable dimensions, and vary the memory assumptions; agreement statistics carry bootstrap intervals.

**Results:** Four results stand out in this single-task case study. First, the systems agree far more on the shape of the machine (one large model resident at a time, a coordinator/worker topology, durable SQLite state, private-network remote access) than on the products that realise each choice: median modal agreement 10 versus 5 of 10 systems. Agreement is not evidence that the shared choices are correct. Second, the study-internal rater, itself an LLM, flagged 19 tools and models as hallucinated; on web verification none was confirmed nonexistent, 15 are real projects, many released or renamed after that rater's training cutoff, and four remain unresolved. Independent verification did find genuine factual errors elsewhere, none of them among the flagged names. Third, citation quantity did not predict citation quality; the response with the largest reference apparatus (99 URLs) was the least reliable. Fourth, in the one system captured in three chat modes, the modes differed on six of the nine rubric dimensions with the prompt held fixed. Rubric totals are rater-dependent: only a few responses at the extremes keep their third of the ranking when the rater set changes.

**Conclusions:** On this currency-sensitive task, an LLM asked to grade another LLM's factual grounding penalised the newest, best-grounded answers, because the grader's own knowledge was stale. The study shows that this failure occurs; it does not estimate how often it occurs across tasks. Evaluation pipelines that place an LLM in the grader's seat for currency-sensitive questions should put an external verification step in front of it. We release the corpus, the rubric, four rater score sets, a web-verified register, and standard-library analysis scripts.

**Keywords:** large language model evaluation; LLM-as-judge; training-cutoff bias; reference hallucination; inter-rater agreement; prompt sensitivity; systems architecture; reproducible benchmark corpus

## Introduction

Closed benchmarks dominate LLM evaluation: a task with a hidden answer key, a scalar score, and a leaderboard. Systems architecture is not that. Given a hardware envelope and a requirements list there is no single correct design, but there are many claims inside any proposed design that are individually checkable: does this model fit in 32 GB, does this tool exist, does this version number resolve, does the response contradict itself.

This paper treats "design a hard system under a fixed consumer-hardware constraint" as an LLM task and measures it. The task is deliberately stress-inducing along several dimensions. The hardware is new: the Apple M6 Mac mini was announced on 25 August 2026, six days before the study. The memory ceiling of 32 GB unified memory is tight enough that a single wrong model choice breaks the design. The prompt explicitly asks for sources and for a list of things not to build.

The contributions are a reusable protocol for evaluating open-ended architecture responses (verbatim capture, structured extraction into a 39-axis decision matrix, a nine-dimension 0/1/2 rubric, multi-rater scoring with reported agreement, and automatable falsifiable-sub-claim checks); an empirical map of where eleven systems agree and disagree; a demonstration that, on this task, apparent fabrication was mostly a failure of the LLM rater; constraint-reasoning and recency results, including a memory analysis that reports how much non-model memory each design leaves; a citation-quality analysis and a reasoning-mode sensitivity result; sensitivity analyses for the raters, the rubric dimensions and the memory assumptions; and a synthesised reference architecture together with a frank limitations section that includes a methodological error we made and its fix. The study is a single-task case study: with thirteen captures on one prompt and one hardware specification it shows patterns and failure modes on this instrument, not population-level laws, and we are explicit throughout about which claims are corpus observations and which are candidates for generalisation.

Agentic benchmarks such as SWE-bench and its variants [1], WebArena [2], and others including Terminal-Bench, OSWorld, Tau-Bench and AgentBench all score against an execution oracle: the task has a hidden pass or fail, and the scope has widened from function-level generation to environment-grounded interaction, but the answer key is always present. A survey of the agent-systems landscape [3] and benchmarks of frontier LLMs on real-world assistant tasks [4] describe the same oracle-based setting. Constrained design has no such oracle. We take the stance of scoring only falsifiable sub-claims, and measuring consensus rather than correctness, from systematic-review methodology: PRISMA-S for reporting a reproducible search [5], PRESS for peer-reviewing a search strategy [6], and the National Academies framing of reproducibility and replicability [7].

Using an LLM to score another LLM's output is now standard and its failure modes are catalogued. A survey of LLM-as-a-judge practice [8] documents position bias, verbosity bias, and self-enhancement; a large-scale study across twenty NLP evaluation tasks [9] finds that LLM judges vary substantially by task and must be validated against human annotations before use; and a controlled analysis [10] shows that a judge's ranking can be reversed simply by changing response order, and proposes position calibration as a fix. The standard fixes are randomised ordering, repeated runs, and rubric-based scoring that constrains the judge to factual criteria, which is exactly the instrument we use. Our case study adds an example of a bias not on those lists: a training-cutoff recency bias in which, when the judged content is more current than the judge's own knowledge, the judge can emit false-positive fabrication flags.

The hallucination literature supplies our fabrication vocabulary. A survey of hallucination in large language models [11] separates factual contradiction from factual fabrication, meaning generated content whose facts cannot be verified against any source; that fabrication category is the one our verification register applies to unresolvable tool and model names. Empirically, a controlled study of ChatGPT-generated bibliographies [12] found 55 percent of GPT-3.5 citations and 18 percent of GPT-4 citations fabricated outright, with 24 to 43 percent of the non-fabricated citations still carrying substantive errors; a comparative analysis for systematic reviews [13] reported reference-hallucination rates between 28 and 91 percent and reference precision below 14 percent for every model tested. Recently published content is a recognised knowledge-boundary cause of this behaviour. Our contribution moves that same cutoff mechanism from the author to the judge: it is not only that a model with an old cutoff invents post-cutoff sources, it is that a rater with an old cutoff can flag real post-cutoff artefacts as invented.

Line-level and repository-level code generation is heavily studied, with SWE-agent, AutoCodeRover, Agentless, and OpenHands exploring different issue-resolution agent designs. Work on LLMs at the architecture level is newer and smaller. Dhar and colleagues asked LLMs to write the decision section of architecture decision records from the recorded context and found that GPT-4, without examples, produced relevant and accurate decisions that still fell short of human architects [14]. A multivocal review of generative AI for software architecture found architectural decision support and architecture reconstruction to be the most common uses, and reported that rigorous testing of the generated outputs was usually missing and that sound evaluation frameworks are lacking [15]. Both lines of work judge a design decision against a human reference or a human reader. Whole-system design under a fixed resource envelope, where no reference design exists, is less studied; the nearest analogue is human-expert capacity planning. We treat "produce a deployable architecture from a hardware spec plus a requirements list" as an evaluable LLM task and evaluate it through its falsifiable parts.

## Materials and Methods

We follow published guidance on reporting empirical software-engineering studies that involve LLMs [16]: this section declares the LLM usage and role, reports model, version, interface and browsing state per capture, releases the prompts verbatim, records session provenance in each capture's metadata, and includes an open-weight system in the corpus.

### The task instrument

The frozen prompt has a responder-context header that fixes the date at 31 August 2026, asks the model to declare its browsing state and version, and requests a Sources list. The task body asks for a 24/7 autonomous development-and-research workstation on a 32 GB Apple M6 Mac mini (12-core CPU, dual 16-core Neural Engine, 170 GB/s memory bandwidth, 512 GB internal plus 1 TB external SSD), coordinating "100+ logical agents without running 100 LLMs", remotely controllable, and securely sandboxed. It asks for deliverables A to K including an exact install plan and a list of what not to install. Two controlled variants are also frozen: one is a full paraphrase using request-for-comments framing with reshuffled sections and no shared sentences, and one is the base prompt with its anti-anchoring steer removed. Both were re-run on a five-system subset; those results appear under prompt sensitivity. Every other matrix and ranking in this paper is for the base-prompt captures.

### The response corpus

Thirteen captures were collected on 31 August 2026 from eleven systems (Table 1). One system, DeepSeek, contributes three captures in three chat modes of one product, presumed but not confirmed to share a base model. Consensus analysis counts one canonical column per system, giving 10 non-anchor systems; the fabrication and internal-consistency analyses use all 13 captures, because the three DeepSeek modes are a within-product comparison no other vendor provided.

The anchor capture, from Anthropic's Claude Sonnet 5, ran inside the same tool used to build this study's repository, with live browsing and partial authorship of the requested output format. It is retained as the consensus anchor and the only sourced baseline, and is excluded from every independent-sample aggregate. The unit of analysis is the system capture, meaning a product interface plus its routing, model, system prompt, browsing state and mode, not an isolated model.

### Extraction and rubric scoring

For each capture we retain a verbatim raw response, which is never edited after merge except for a dated correction note, the model's own cited-sources list, and structured reviewer notes, plus one short phrase per decision axis in a 39-axis matrix. Scoring uses a nine-dimension 0/1/2 rubric: hardware-constraint adherence (D1), recency (D2), tool factuality (D3), model factuality (D4), benchmark factuality (D5), citation quality (D6), actionability (D7), security model (D8), and internal consistency (D9). Axis coding used predefined inclusion criteria; for example, "Apple-Silicon-native inference" counts MLX-family runtimes and llama.cpp with Metal, not CPU-only inference. The 39 axes were defined by the author, which introduces researcher degrees of freedom; the coding guide and the per-response phrases are released so the coding can be audited. The rubric mixes two layers, and we do not claim to establish an objective ground truth for overall architectural quality: some dimensions are objective, such as model existence, version existence, memory feasibility under stated assumptions, and self-contradiction, while others are rubric-based judgements of design quality, such as actionability and security adequacy.

The two instruments were written before data collection finished: both are in the repository's first commit on 31 August 2026, which also holds the first four of the thirteen captures. Each axis is a decision every response has to make to answer the prompt, such as which inference engine to run, how many models to keep resident, and which task queue to use. Each rubric dimension targets one of the study's questions (fabrication, constraint reasoning, recency, citation quality, internal consistency) or a deliverable the prompt asks for (an install plan, a security model), and each of the three levels has a written anchor. The instruments were revised twice, and both revisions are versioned. On 1 September 2026, after web verification, the zero level of D3 and D4 was reworded to require a web-verified nonexistent entity. After the agreement analysis, sharper anchors were written for D1, D7, D8 and D9; they are released as a second version and were not applied to any score in this paper. No expert-panel review, pilot study or psychometric validation of either instrument was carried out. The evidence we can offer is limited to three kinds: the factual dimensions D1, D3 and D4 are tied to external checks (the memory estimator and the verification register) rather than to rater judgement alone; agreement is reported per dimension with uncertainty; and the coding guide and every per-response phrase are released for audit. We therefore use the rubric as a structured reading aid for this case study, not as a validated measure of architectural quality, and we rest no conclusion on a fine-grained ranking.

### Rater procedure and inter-rater agreement

The nine-dimension rubric was applied independently to all thirteen captures by four raters: one author-derived baseline and three frontier LLMs (GPT-5.6 Sol, Grok 4, and a DeepSeek chat run) given the identical scoring packet. "Independent" here means each scored the same packet without seeing another rater's scores; it does not mean design-independent, because the author-derived baseline also wrote the rubric and the reviewer notes. We therefore treat that rater as an author-derived baseline rather than a neutral fourth opinion, and use GPT-5.6 Sol as the canonical comparison rater. No independent human expert rated the responses; the Discussion sets out which results this affects. Agreement is reported as exact and within-one-point agreement, Cohen's kappa unweighted and quadratic-weighted [17], Gwet's AC1 unweighted and quadratic-weighted [18], Krippendorff's ordinal alpha [19], and, for the per-response totals, Spearman's rho and Kendall's tau-b between every rater pair. The estimator is a released standard-library script.

The order of work is recorded in the repository history. The rubric and axes were committed on 31 August 2026. The web-verification register that overturned the initial fabrication flags was committed at 09:55 on 1 September. The author-derived baseline scores, which were derived from each capture's reviewer notes after those notes had been corrected against the register, were committed together with the three LLM raters' scores at 12:05, and the first manuscript draft at 12:14. Scoring therefore preceded the writing of conclusions, but the author-derived baseline was not blind to the verification results. For that reason every ranking result is also reported without it (Sensitivity analyses). The 37 disagreements in the canonical pair were adjudicated by a fixed, documented rule: the rubric text decides, and for the factual dimensions the verification register decides; each decision and its reason is listed in the released adjudication report. Because adjudication decides cell by cell, an adjudicated total can fall below every rater's total. This happens for three DeepSeek captures, where adjudication applied recommend-then-forbid contradictions and unresolved model names that the raters had scored more leniently (Figure 1).

Two scoring passes exist and are not interchangeable. In the full four-rater pass an intermediate version of the packet listed twelve real post-cutoff tools in one rule while instructing raters to treat them as real; all three second-rater runs saw it. That pass supplies the agreement statistics and, with this caveat, the rater ranges and the sensitivity analyses; it does not supply the canonical D3 and D4 levels. A clean re-run of dimensions D3 and D4 used an uncontaminated packet that names nothing, forbids reading the verification register, mandates web verification, and scores an unresolved entity as 1. That clean pass is canonical for the D3 and D4 levels. One of the two fresh raters used for it, Perplexity, was discarded because it scored tool factuality 0 for seven responses by treating its own search misses as evidence of non-existence.

The discarded Perplexity run participated only in the clean D3 and D4 re-run; it was never part of the four-rater pass and enters no agreement statistic. Every inter-rater figure reported below is computed over the author-derived baseline, GPT-5.6 Sol, Grok 4, and the DeepSeek chat run, and is therefore unaffected by that exclusion. The canonical D3 and D4 levels used for the adjudicated totals come from the surviving clean-packet rater, GPT-5.6 Sol. The released scripts regenerate every figure from the scored packets, so the effect of including or excluding any single rater can be checked directly.

### Fact verification

Every falsifiable sub-claim is recorded verbatim and checked. Tool and version existence is checked against a registry or repository fixed to the capture date, and the per-entity verdicts (entity exists, identity correct, attribute correct, claim supported, and a final category) are released as a register. URLs in a response's citation apparatus are classified on three axes: whether the URL resolves, whether it supports the claim it is attached to (fully, partly, or not), and whether the source is primary, secondary, tertiary, or irrelevant. "Non-supporting or unresolvable" is the union of does-not-resolve and does-not-support. The operational decision rules for each axis, with examples, are released with the data. A URL resolves only if it returns the document the reference names, judged as of the capture window from an archived copy where the live page has changed. A reference supports a claim fully only if the page states the claim, including any number, version or attribute the claim gives. A commit, pull request or skill file cited for a performance or capability claim does not support it unless the file itself contains the evidence. The classification of the Meta capture's 99 references was a single-coder pass recorded as summary notes, without a per-URL record; the 99 references are released as an audit sheet against these rules.

### Memory-budget estimation

A standard-library estimator adds the weights of a response's co-resident model set, meaning what the response says stays loaded, and a key-value cache estimate, and compares the sum plus a non-model reserve with 32 GB. Weight sizes are taken from the response's own figures where it gives them and otherwise from published 4-bit artefact sizes; each preset in the released script documents its source. Where a response states a size that the verification register contradicts, the arithmetic uses the stated size, because it tests the response's own budget, and the text reports the verified size separately. The key-value cache is the context length the response states multiplied by a per-1,000-token rate set by the largest resident model. The estimator's default reserve is macOS and core services at 7 GB, the Python supervisor and workers at 1.5 GB, SQLite with a vector index at 0.5 GB, and a headless browser at 2.5 GB, 11.5 GB in total; a design fits with headroom when at least 2 GB remains free.

Every one of these figures is an assumption, so instead of a single verdict we report, for each design, the break-even reserve: 32 GB minus weights minus key-value cache, which is the largest non-model allowance under which the design still fits. We compute it with the key-value rate halved, as set, and doubled, and compare it with the 11.5 GB default and with a 7 GB bound for a lean headless host (Figure 2). Three presets encode an alternative reading of a response rather than its stated design (for example, both of a response's large models loaded when the response itself says one at a time); they are marked and are not used for any verdict on a response. A design that swaps models gets one preset per phase, including any helper model the response shows running alongside the heavy one.

### Sensitivity and uncertainty analyses

All analyses in this subsection are in one released, seeded, standard-library script. Agreement statistics, rank correlations and rater means carry 95 percent percentile bootstrap intervals from 10,000 resamples of responses, the unit of analysis; resamples in which kappa is undefined because a rater gave one score throughout are skipped and counted. Counts out of ten systems carry Wilson 95 percent intervals. The structural-versus-product consensus gap is summarised as a difference in medians, with a bootstrap interval that resamples axes within each group, and tested as a difference in means with a one-sided permutation test (20,000 permutations of the axis labels). The test treats the axis labels as exchangeable, which is only approximately true: the axes are not independent, and structural answers were coded more broadly than product names.

Three sensitivity analyses address the rater and rubric choices. To remove the author-derived rater, response totals are recomputed from the canonical LLM rater alone (with its clean D3 and D4 scores), from the mean of the three LLM raters, from that mean with every rater's D3 and D4 taken from the clean pass (Grok 4 and the DeepSeek run scored those dimensions only in the contaminated pass), and from each LLM rater alone. To test the weakly reliable dimensions, totals are recomputed with each dimension left out in turn, with the two weakest (D1 and D9) dropped, and with all five dimensions whose canonical-pair kappa is below 0.40 dropped. To group responses without chosen score thresholds, responses are placed in rank-based thirds (the upper, middle and lower four of twelve) by average rank, with ties that straddle a boundary placed in the middle third; the rule has no tuned threshold, and every comparison reports which responses change third. A last check draws each response's total at random from one of the four raters (using the canonical rater's clean D3 and D4 scores), 10,000 times, and records how often each response keeps its third.

### Use of AI tools in this study

This is disclosed in full because the study's subject is AI systems. The consensus anchor is a frontier LLM run inside an AI coding tool with live browsing and partial authorship of the requested output format; it is excluded from every cross-response aggregate. The repository, meaning the analysis scripts, the data plumbing, and drafting of parts of this manuscript, was produced with an AI pair-programming assistant; every script uses only the Python standard library, is in the release, and its outputs are reproducible from the released comma-separated files. Three of the four rubric raters are frontier LLMs, by design, because that is the object of study. All numeric results in this paper were regenerated from the released artefacts by running the released scripts; no result is quoted from an un-scripted model statement. No AI-generated images are used; the figures are drawn by a released script from the released data. No part of the analysis beyond copy editing and code assistance was delegated to a model without human verification.

## Results and Discussion

The first nine subsections report observations. Interpretation, including what the observations do not show, is collected in the Discussion subsection that follows them.

### Architectural consensus

Across the 39 axes the systems are unanimous or near-unanimous, at nine or all 10 non-anchor systems, on the shape of the machine. They agree on Apple-Silicon-native inference as the primary path, with llama.cpp and Ollama compatibility; on keeping one large model resident at a time with small models optional or on demand, the lone outlier being a design that proposes two or three co-resident instances; on model swapping with an anti-thrash policy; on a custom supervisor with thin integration of specialist runtimes rather than one mega-framework; on a hierarchical coordinator/worker topology that is explicitly not a swarm; on treating "100 agents" as cheap state and configuration rather than 100 resident models; on one concurrent heavy-inference slot; on an evidence-first research pipeline with a stored evidence ledger, where final prose is generated only from verified evidence; on SQLite plus the filesystem as day-one memory, deferring vector and graph complexity; on a dedicated non-admin user plus workspace isolation as the security boundary; on a Tailscale-only private network with no public exposure and a small private dashboard; on launchd with KeepAlive plus an independent watchdog, with caffeinate or pmset on AC power, and a durable queue with leases, checkpoints and requeue that never replays destructive actions; on 32 GB unified memory being the bottleneck rather than CPU or GPU compute; and on the 1 TB external SSD being cold storage rather than the latency-critical disk. All 10 non-anchor responses identified memory as the primary constraint.

Where the systems disagree, they disagree on products, and we record those axes as adjudication points rather than facts (Table 2). Tagging each of the 33 architecture axes as structural (topology, state model, security boundary, concurrency stance, memory architecture; 24 axes) or product (which named tool or model realises a layer; nine axes) and taking the modal-agreement count per axis over the 10 non-anchor systems, the structural axes have a median modal agreement of 10 out of 10, with 18 of 24 at nine or higher, while the product axes have a median of 5 out of 10, with only one of nine at nine or higher (Figure 3). The median gap of five points has a bootstrap 95 percent interval of two to six points; the means differ by 3.4 points, and the permutation test of that difference gives p < 0.001, subject to the exchangeability assumption stated in the Methods. With ten systems, a single axis count is imprecise: an axis on which eight of 10 agree has a Wilson 95 percent interval of 49 to 94 percent. The classification and the per-axis counts are in a released script so the tagging can be audited.

### Apparent fabrication and the rater that generated it

The study-internal rater, an LLM with a training cutoff around January 2026, audited every capture and flagged 19 tools and models across five responses as fabricated, grouped as 14 entries in Table 3, most heavily in the two DeepSeek fast modes and in the Meta Llama 4 capture. We initially drafted a "cross-vendor shared hallucination" finding around two tools each named by three vendors.

Web verification against 2026 sources overturned that reading (Table 3). None of the 19 flagged names was confirmed nonexistent. Twelve resolved to real projects at the first pass; of the seven names unresolved at first pass, a follow-up verification pass resolved three (Cloak, memo, and pi-search-hub) to real projects, leaving four unresolved: Helmrig, DiffResearch, cplt, and agent-policy-engine. Many of the 15 real projects were released or renamed after the rater's training cutoff, and the false-positive flags cluster on the most current responses.

This is a statement about the flagged names, not about the corpus. We keep two populations separate. The initial-rater fabrication flags are the 19 names: zero were confirmed nonexistent, 15 are real, and four remain unresolved. Separately, independent verification found genuine factual defects that were never raised as fabrication flags: one genuinely nonexistent future model in the DeepSeek deep-reasoning capture, several model-attribute errors in the Zhipu capture, and internal contradictions in several captures. Thus the corpus is not fabrication-free; rather, the initial rater's fabrication verdicts were unsupported.

The same failure reproduced in a fresh rater given an explicit instruction to web-verify every name and to score an unresolved name as 1: in the clean re-scoring, one of two fresh raters treated its own search misses as evidence of non-existence for seven responses, and its scores were discarded. Dimensions D3 and D4 of the rubric now require the rater to web-verify each name before scoring, and "not in my training data" scores 1 for unresolved, never 0.

The analysis is not empty of real defects (Table 4). These survive verification and remain in the analysis: a load-bearing model-size error and a self-contradiction on model memory size in the Zhipu capture; an incorrect M6 memory-bandwidth figure and an unreliable citation apparatus in the Meta capture; recommend-then-forbid contradictions in two DeepSeek captures; a nonexistent future primary model in the DeepSeek deep-reasoning capture; a memory oversubscription and a model-architecture error in the DeepSeek Instant-plus-DeepThink capture. The Grok 4 capture records no surviving factual defect: it states the full M6 specification, including 170 GB/s, correctly, and its alternate-tool list resolves entirely, so it does not appear in Table 4. Its only weakness is zero cited sources. We note this explicitly because an earlier draft mis-attributed a bandwidth error to Grok 4; the error belongs to the Meta capture only.

### Constraint reasoning

Figure 2 shows, for each design, the break-even reserve: how much memory its stated co-resident set leaves for everything except the models. No stated design fits under the estimator's 11.5 GB desktop default, which counts a browser. With the browser left out (a 9 GB reserve), Gemini (10.4 GB) and the anchor (9.6 GB) fit. Seven further configurations leave between 7.1 and 8.7 GB at the default key-value rate (Mistral 8.7, Perplexity 8.6, DeepSeek Expert 8.1, GPT-5 7.6, Grok 4 7.2, Kimi 7.1, and DeepSeek Instant 7.1 in the phase where its Qwen model runs with its 9B summarizer); they fit only with a reserve near the 7 GB lean-host bound or at a shorter context than the one they state. For these designs, whether they "fit" depends on the reserve assumption more than on the design. Meta (4.8 GB), DeepSeek Instant in its Gemma phase (3.5 GB), Qwen (2.7 GB) and DeepSeek Instant-plus-DeepThink (minus 0.7 GB) leave less than the lean-host bound. DeepSeek Instant-plus-DeepThink is the only stated design whose models and key-value cache exceed 32 GB before any operating-system or application memory at every key-value rate tested (minus 1.8 to minus 0.2 GB), and its text calls the oversubscription acceptable. The Zhipu design keeps three model instances co-resident and states that it "fits within 32GB RAM with swapping". On its own stated sizes it leaves 6.1 GB (4.2 to 7.0 across the key-value range), but those sizes are wrong: the verification register records its primary model as an 80B mixture-of-experts model and its light model as a 106B one, so at about four bits per weight the primary model alone needs roughly 40 GB and the design cannot fit.

Under the adjudicated scores, D1 gives 0 to the Zhipu and DeepSeek Instant-plus-DeepThink captures. Inter-rater agreement on this dimension is among the lowest of the nine, at kappa 0.15, because "sums to exactly 32 GB with no reserved margin" was scored 1 by one rater and 2 by another; the hardened rubric requires a named free-RAM floor for a score of 2.

### Recency

The web-verified M6 facts are: announced 25 August 2026, 170 GB/s memory bandwidth at 24 to 32 GB (153 GB/s at 16 GB), and 32 GB maximum unified memory. Against those facts, two non-anchor responses plus the anchor engage the real M6 specification, hedge every throughput number, and cite sources. Six responses make current tool and model picks but provide no usable sources, and two of those also carry a roughly 12- to 18-month model lag. Two responses are behind on models, with previous-generation primaries and stale cloud-fallback lists. Only the Meta capture got a hard M6 fact wrong, at about 300 GB/s; the Grok 4 capture, which the first rater mistakenly grouped with it, states 170 GB/s correctly. Recency co-occurs with retrieval or browsing and with not being penalised by a stale rater, but it does not cleanly predict agreement with the cross-model consensus.

### Citation quality

Only the anchor and four non-anchor responses cite anything resolvable (Table 5). Citation quantity did not predict citation quality, and because only five of 13 responses carry any citation apparatus we report the pattern rather than a correlation coefficient. The pattern is driven by the extremes: the Meta capture has the largest apparatus and, on our reading, the least reliable one. That reading comes from a single-coder pass recorded only as summary notes, without a per-URL record, so we report it qualitatively: the notes describe most of its 99 references as repository, commit, pull-request or skill-file URLs cited as evidence for claims those pages do not make, the same tool given several different repository URLs, and one real preprint URL under the wrong title. The 99 references are released as an audit sheet with the decision rules so the classification can be repeated. The GPT-5 capture cites zero URLs, but every inline attribution points at a real, checkable source. Scoring "has a Sources section" as a proxy for "is grounded" would rank the Meta capture above the GPT-5 capture. Dimension D6 scores a mostly-unsupported apparatus as 0.

### Internal consistency and reasoning-mode sensitivity

Material self-contradictions appear in three of thirteen captures: two DeepSeek captures each recommend a tool that their own do-not-install list forbids; the Zhipu capture gives one model two different memory sizes and pairs "primary model stays loaded, others on demand" with a three-instance co-resident diagram; and the Meta capture has coherent prose but an incoherent citation apparatus.

DeepSeek is the only system captured in more than one mode: three captures in three chat modes of one product (Table 6). They are presumed to share a base model, but two of the three captures record the model version as not shown, so this is a comparison of chat modes, not a controlled same-weights experiment. With the prompt held fixed, the three captures received adjudicated totals of 9, 8 and 6 and differ on six of the nine dimensions, including hardware constraint, recency and model factuality; all three fall in the lower third. The differences do not follow the amount of reasoning: after the clean re-run the fast mode scores above the deep mode, because the deep mode's more elaborate upgrade path reached for future models that do not exist while the fast mode's picks all resolved. This is one product in one task; whether mode matters as much as the model label in other model families is untested.

### Inter-rater agreement

The four rater means span 11.1 to 14.7 of 18 (Table 7). For the canonical pair, over 117 paired ratings, exact agreement is 68.4 percent and within-one-point agreement is 96.6 percent. Cohen's kappa is 0.49 unweighted (95 percent interval 0.33 to 0.63) and 0.64 quadratic-weighted (0.47 to 0.76); Gwet's AC1 is 0.54 unweighted and 0.73 quadratic-weighted (0.61 to 0.83); Krippendorff's ordinal alpha is 0.60 for the pair (0.41 to 0.73) and 0.46 for all four raters (0.36 to 0.54). The weighted measures agree with one another, and we read agreement as moderate and dimension-dependent.

By dimension, recency, tool factuality and benchmark factuality have the highest canonical-pair kappa, 0.66 to 0.70; citation quality, security model and actionability are weak; and hardware constraint and internal consistency are the weakest, at 0.15 and 0.14 (Figure 4). With thirteen responses every per-dimension interval is wide; recency, for example, runs from 0.24 to 1.00, and the intervals for D1 and D9 include zero. This ordering is specific to the canonical pair. Between pairs of LLM raters, kappa on recency, tool factuality and benchmark factuality ranges from minus 0.23 to 0.58; on benchmark factuality Grok 4 and the DeepSeek run gave every response the same score, so their kappa is zero or undefined, and the LLM raters' tool-factuality scores come from the contaminated pass.

Rank-order stability is limited. Rank-correlating the per-response totals between every rater pair gives a mean Spearman rho of 0.36 and a mean Kendall tau-b of 0.28. The canonical pair is the tightest, at rho 0.71 (0.24 to 0.93), and the author-derived baseline against the DeepSeek run is 0.08 (minus 0.64 to 0.75). Raters also have a severity personality: the DeepSeek run assigned a 2 on five dimensions almost uniformly, behaving as a low-information rater.

The answer-key leak in the intermediate packet was bounded, not removed. The canonical rater's clean pass changed three D3 and D4 cells relative to its contaminated pass (Mistral D3, Meta D4 and DeepSeek Instant-plus-DeepThink D4), so it reproduced both scores on 10 of 13 responses. The adjudicated table changed on four D3 and D4 cells, each for a web-verified reason recorded in the re-run report. This comparison cannot separate the effect of removing the leaked list from the effect of new verification evidence. Dimensions D1, D2, and D5 to D9 were never contaminated.

### Sensitivity analyses

Table 8 reports each response's adjudicated total, its rank-based third, and the range of totals the four raters gave it; Figure 1 plots the same data. We report continuous totals and rank-based thirds rather than named performance bands, because no rule justifies a quality boundary between, for example, totals of 14 and 15. The thirds are a rule applied to ranks, not a quality grade.

Removing the author-derived rater changes most of the table (Table 9). With the canonical LLM rater alone, the rank correlation with the adjudicated totals is 0.80 and six of twelve responses change third; with the mean of the three LLM raters it is 0.85 and four change third (Gemini 3.1 Pro rises to the upper third, Grok 4 falls to the middle, DeepSeek Instant rises to the middle and Kimi Instant falls to the lower). Grok 4 and the DeepSeek run scored D3 and D4 only in the contaminated pass; taking those two dimensions from the clean pass for all three raters raises the correlation to 0.92, and only DeepSeek Instant (to the middle) and Kimi Instant (to the lower third) change third. In all three of these combined score sets, Perplexity and Mistral Large 3 stay in the upper third and Zhipu, DeepSeek Expert and DeepSeek Instant-plus-DeepThink stay in the lower third. Single LLM raters reorder even these: with Grok 4 alone (rho 0.59) seven responses change third, including Perplexity, DeepSeek Expert and DeepSeek Instant-plus-DeepThink, which all move to the middle; with the DeepSeek run alone (rho 0.32) eight change. Krippendorff's alpha across the three LLM raters alone is 0.45, against 0.46 with all four. When each response's total is drawn at random from one of the four raters, only Zhipu keeps its third in more than four draws of five (85 percent); Perplexity (76 percent), Qwen 3.7 Plus (75 percent) and Mistral Large 3 (74 percent) follow, and Grok 4 keeps its place in only 29 percent. Membership of a third is therefore stable only at the extremes, and only for score sets that combine raters.

Leaving out any single dimension gives totals that rank-correlate 0.96 to 1.00 with the full totals and moves at most one response: DeepSeek Instant moves to the middle third when D9 is left out. Dropping both D1 and D9 moves three responses (DeepSeek Instant, Grok 4 and Kimi Instant; rho 0.96), and keeping only the four more reliable dimensions D2 to D5 also moves three (DeepSeek Instant, Kimi Instant and Mistral Large 3; rho 0.87). Perplexity, Zhipu, DeepSeek Expert and DeepSeek Instant-plus-DeepThink keep their third in every one of these sets.

### Prompt sensitivity

Five systems were re-run on the full paraphrase and on the anti-anchoring-steer ablation, for 15 captures in total. Within each system, the variant captures keep the coordinator/worker topology, logical agents as data, SQLite state, launchd and Tailscale, and change mainly which products realise each layer, with two exceptions: Zhipu's base capture keeps three model instances co-resident while its two variants keep one heavy model plus a small one, and the Perplexity ablation capture is incomplete, does not mention a dedicated user, and is compared only on the axes it covers. Effect size is strongly system-dependent: one system's primary inference-engine pick is different in each of the three framings, while two others are almost invariant. The anti-anchoring steer does real work, but its sign is not uniform: removing it made two systems name more products and one system name fewer. No system's model can be confirmed as unchanged across the three framings. The Zhipu z.ai and Google Gemini captures self-reported different knowledge cutoffs and model labels across sessions; the GPT-5 base capture used the free-tier GPT-5.6 Luna and both of its variants the paid-tier GPT-5.6 Sol; and Perplexity does not disclose its model. These are comparisons of product sessions under different prompts, not of fixed models. Across all ten paraphrase captures, zero fabrications were confirmed on web verification.

### Discussion

Agreement is not correctness. The structural consensus shows that ten systems, given the same prompt, chose the same options; it does not show that those options are right, and a shared training diet or a shared reading of the prompt could produce agreement on a poor choice. Part of the consensus is a reading of the constraint rather than general architectural reasoning. One resident heavy model, a single heavy-inference slot, model swapping with an anti-thrash policy, and treating "100 agents" as cheap state are direct consequences of a tight memory budget and would relax on a larger machine. The other structural agreements are standard distributed-systems practice that does not depend on memory size: a coordinator/worker topology, a durable queue with leases that never replays destructive actions, an evidence ledger for research, a dedicated non-admin user, a private network, and supervised always-on operation. Because the study uses one hardware specification, we cannot separate consensus that the 32 GB ceiling forces from consensus that would hold on any host. What the consensus map offers an engineer is a list of where the systems diverge, the product choices in Table 2, which are the decisions still to be made; it does not certify the structural choices, which need the same checks as any design.

The fabrication result is a demonstration, not a prevalence estimate. It rests on one study-internal rater, one fresh rater that repeated the failure, one task and one capture window. It shows that an LLM rater can treat absence from its own knowledge, or an unsuccessful search, as evidence that a post-cutoff entity does not exist, and that the resulting false-positive flags fall on the most current responses. It does not show how often this happens, how large the effect is on other tasks, or whether other raters share it. The catalogued LLM-as-judge biases of position, verbosity and self-enhancement [8-10] concern how the judge is influenced by the candidate's form; this one concerns what the judge cannot know, so randomised ordering and repeated runs would not be expected to remove it. Training cutoff is one cause and retrieval failure is another.

No independent human expert scored the responses, and the results differ in how much this matters. The fabrication result does not rest on any rater's scores: it rests on web verification of the 19 flagged names against dated public records (Table 3), which a reader can repeat from the register, so it would not change under human evaluation. The consensus map is a coding of what each response recommends, not a quality judgement. The rubric totals are what could change: totals for the same response differ by up to eight points across the four raters (Figure 1), and the sensitivity analyses show that responses keep their third only at the extremes, and only when raters are combined. A human panel could order most of the table differently, and the ranking should not be relied on beyond upper-third membership for Perplexity and Mistral Large 3 and lower-third membership for the Zhipu, DeepSeek Expert and DeepSeek Instant-plus-DeepThink captures.

### Synthesised reference architecture

The following is an analytic synthesis, meaning majority positions plus adjudicated calls, not a consensus ground truth and not empirically validated as optimal. For inference, use one MLX-family runtime behind an internal adapter, with one large mixture-of-experts model resident at about 17 to 20 GB at 4-bit plus one small dense model swapped in on demand, and never two large models co-resident; benchmark the chosen runtime on the actual M6 before trusting any throughput claim, and measure the real non-model reserve, since Figure 2 shows such a design fits only if that reserve stays below about 9 GB. Represent the agents as SQLite rows or definition files under a hierarchical coordinator/worker topology with one concurrent heavy-inference slot plus two or three small or tool workers. Let a thin custom Python supervisor own task state and scheduling, with a framework used only for selected stateful workflows and kept replaceable. Make coding execution capability-tiered, with a git-native interactive editor for edits and a containerised autonomous agent for multi-step jobs. Run an evidence-first research pipeline in which every claim traces to a stored snippet, a second-pass verification agent re-opens sources, a contradiction pass runs, and prose is synthesised only from the verified ledger. Use the filesystem plus SQLite with full-text search on day one, add an embedded vector extension when needed, and defer a standalone vector daemon and a knowledge graph until a real need is demonstrated. Use a SQLite write-ahead-log task queue with leases and checkpoints, requeue interrupted work, and never replay destructive actions. For security, use a dedicated non-admin macOS user plus workspace isolation, capability tiers with a kill switch and per-task runaway limits, and secrets in the system keychain; scope stronger sandboxing to untrusted code rather than making it universal. For always-on operation use launchd with KeepAlive plus a separate watchdog plus caffeinate or pmset on AC power. For remote access use Tailscale only, with zero inbound ports and a small dashboard on the private network, and route approvals through the dashboard. Put the operating system, runtime and hot working state on the internal SSD and the model library, research corpus, datasets and backups on the external SSD. Treat cloud use as an explicit policy-gated escape hatch that keeps the system useful at zero cloud spend. The 32 GB unified-memory ceiling is a hard engineering constraint, not a target to fill.

### Limitations and threats to validity

This is a single-task case study: one base prompt, one hardware specification, one capture day. Two controlled paraphrases on a five-system subset left most architectural choices unchanged and produced no confirmed fabrications, which suggests the consensus and fabrication findings are not phrasing artefacts; the product-level results are phrasing-sensitive and should be read as "for this instrument", and a second hardware specification has not been tested. Consumer chat products are not reproducible instruments: no system's model could be confirmed as unchanged across the paraphrase runs. The anchor capture is not blind, and is handled by exclusion from every cross-response aggregate.

The rubric and the decision axes were written by the author and were not validated by an expert panel, a pilot study or psychometric analysis. No independent human expert rated the responses. Three of the four raters are frontier LLMs, and the fabrication result is a direct demonstration of the associated risk; the mitigations are mandatory web verification for factual dimensions, four raters with reported agreement and intervals, verbatim recording of every falsifiable sub-claim, and sensitivity analyses without the author-derived rater. The author-derived rater wrote the rubric and was not blind to verification, and adjudication was not blind either; without that rater, the rank-based thirds are stable only at the extremes and only for combined LLM score sets. Rater severity varies by about 3.6 of 18. Grok 4 scored the Grok 4 response and the DeepSeek run scored the three DeepSeek responses, which is noted but not corrected. The intermediate rater packet leaked part of the verification key, and the bounded re-run above measures the effect. The memory verdicts depend on assumed reserves and key-value rates, which is why we report break-even reserves rather than a single verdict. The Meta citation assessment comes from a single-coder pass without a per-URL record and is reported qualitatively.

Several facts in this study were verified against live repositories and release pages, which can change. Every capture is a dated snapshot from 31 August 2026, and the verification register records the evidence for each verdict as checked on 1 September 2026. The corpus, register, score files, analysis outputs and scripts are fixed in an archived release of the repository [ARCHIVE DOI TO BE INSERTED BEFORE RESUBMISSION]. The DeepSeek mode effect is one system and motivates, but does not establish, a general law.

### Broader impact

This work contributes a reusable protocol and a released corpus for auditing LLM-as-judge pipelines on open-ended technical tasks, and documents a specific, cheaply mitigated failure mode. The risks are that the released corpus and rubric could be used to game an evaluation, that "an LLM said it is fake" verdicts shown here to be unreliable may still be cited as authoritative, and that the synthesised reference architecture is a dated snapshot whose uncritical reuse past its 2026 currency window would reproduce the recency failure it documents.

## Conclusion

Asked to design the same constrained machine, eleven frontier LLM systems agreed on what the machine is, a memory-bound local-first coordinator/worker workstation with durable state and private-network control, and disagreed on which specific products build it. Agreement is not evidence that the shared design is right; the disagreements mark the decisions a human engineer still has to make, and the shared choices still need the same checks as any design.

The sharper result is about evaluation. In this case study, an LLM asked to judge another LLM's factual grounding penalised the newest, best-grounded answers, because the judge's own knowledge was stale. The study shows that this can happen, not how often it happens. Any evaluation pipeline that puts an LLM in the grader's seat for currency-sensitive questions should put an external verification step in front of it.
